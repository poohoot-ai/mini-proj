## 2. 프로젝트 목표

총무가 Streamlit에서 최대 30명의 주문을 자연어로 일괄 입력하면 FastAPI 기반 Orchestrator와 수집·정규화·주문검증·정산 에이전트가 메뉴를 정규화하고, 총 인원 수와 동일 주문별 합산 명세서를 반환한다. 에이전트·PostgreSQL 장애가 발생하면 최대 3회 시도, 모의 대체 모델, 회로 차단, 독립 검증을 적용하고 결과를 추적 가능한 증거로 남긴다.

## 3. 작업 원칙

- 모든 작업은 승인된 PRD v1.2의 FR-001~FR-016과 NFR-001~NFR-008에서만 도출한다.
- 모든 구현 작업은 `[ ] pending`으로 시작한다.
- 기능 구현과 단위·통합 검증을 같은 작업 또는 바로 이어지는 작업에 배치한다.
- 복구 실행 결과는 Recovery Verification Gate가 독립적으로 검증한다.
- 실제 결제·스타벅스 API·개인정보·메뉴 캐시·외부 자동 알림은 구현하지 않는다.
- 실제 시크릿은 코드·이미지·로그·저장소에 기록하지 않는다.
- `gpt-4o-mini`가 계정에서 사용 불가능하면 구현을 중단하고 PRD 변경 승인을 요청한다.
- 장애 주입은 모의 데이터와 격리된 개발 환경에서만 수행한다.
